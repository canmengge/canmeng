### 12.2 十步流程

1. **定版本号**：三段递增（4.2.2 → `4.3.0` → `4.4.0`…）；`frontend\src\buildInfo.ts` 的 `TEST_BUILD_NO` **写成与清单完全相同的三段号**（自 4.4 起统一，例：`4.4.0`）。
2. **前端正式构建**：`cd 01-源码\frontend` → `npm run build`（含 vue-tsc；**禁止**设置 `VITE_DEV_TOOLS`）→ 产物 `frontend\dist`。
3. **后端检查**：`go vet ./...`、`go test ./...`（发版候选各跑一次）。
4. **编译正式 EXE**：输出到 `06-交付发布\release-<版本>\PVF工坊<版本> ·编辑器110优化版 · By 残梦断忆.exe`（新命名，2026-09-28 起；4.3 及以前为旧命名 `PVF工坊 ·编辑器110优化版<版本> · By 残梦断忆`）。
5. **核验 EXE**：`0x20B` / `subsystem=2`（GUI 无黑窗）/ 图标 `3:6 14:1` / 含本版号与新功能字面量 / 记录大小与 MD5。
6. **组包**：`06-交付发布\release-<版本>\full-staging\<客户目录名>\` = exe + `更新记录.md` + `使用说明.md` + `知识库\` + `注释数据\` + `pvfine-main\HC\`（**基线 = 复制上一版线上客户目录**；**不得含任何源码**）。
7. **更文档**：`更新记录.md` 新增本版章节 + 版本对照表；`使用说明.md` 更新文件名、大小、内部版本号、MD5、更新方式说明。
8. **打两个包**：`pvfine-X.Y.Z-update.zip` = **仅顶层 exe 单条目**；`pvfine-X.Y.Z-full.zip` = 打包 `full-staging\<客户目录>`（zip 顶层即客户目录名，与上一版一致）。
9. **生成清单**：把本版 `更新记录.md` 复制成 ASCII 名 `notes.md` → `cd 06-交付发布\release-<版本>` → `node gen-manifest.js notes.md pvfine-X.Y.Z-update.zip X.Y.Z pvfine-X.Y.Z-full.zip`（产出 `stable.json` + `SHA256SUMS.txt`）。
10. **上传 + 公网复核**：`scp` 两个 zip → `releases/`；`stable.json` → `updates/windows/amd64/stable.json`；（文案有变时）`index.html` → `/pvf/index.html`；然后按 §12.5 逐条验证，**必须把两个包从公网下载回来比对 SHA-256 与包内 exe 的 MD5**。

### 12.3 清单与包口径（不得擅改）

- `stable.json`：`schemaVersion=1`、`version=X.Y.Z`、`channel=stable`、`name=PVF工坊 X.Y.Z`、`notes`=更新记录正文（去 BOM、CRLF→LF、压缩连续空行）、`publishedAt`=ISO 秒级、`artifacts[0]` = update.zip 的 `url / filename / size / digest`（`digest` = sha256 **原始 32 字节的 base64**）。
- `SHA256SUMS.txt`：`<HEX 大写>  <文件名>`，**更新包在前、完整包在后**。
- update.zip 内 exe 名 = 客户现用名（保证同名原地替换），且必须与 full 包内 exe **同一份二进制**。**注意**：一旦按新命名改了 exe 名（4.4 起），老用户目录里会残留上一版 exe —— 交付说明里要写明“覆盖后删掉上一版的 exe”。

### 12.4 实战踩坑（4.3 发布教训，必须遵守）

1. **版本号必须三段**：更新比较走 `golang.org/x/mod/semver`，`4.3` 会被判**非法** ⇒ 旧客户端收不到提示。因此清单与 `appVersion` 一律三段；**界面版本号自 4.4 起也写三段，与清单彻底统一**（4.3 是唯一例外：界面 4.3 / 清单 4.3.0，用户裁定不再重发）。
2. **正式构建绝不能带 `VITE_DEV_TOOLS`**：带 = 出现开发者面板/入口。核验：构建产物中**不得出现** `VITE_DEV_TOOLS` 字面量（`DEV_TOOLS=false` ⇒ 工具栏按钮、状态栏 DEV 标记、DevPanel 均不渲染）。
3. **交付包不得含源码**：full.zip 内 `.go/.ts/.tsx/.vue/.py` 必须为 **0**；知识库里的 `.md/.json/.mjs/.nut` 是社区教程资料，可以带。
4. **官网页面是动态的**：`/pvf/index.html` 与 `/pvf/changelog.html` 都 `fetch` 同一份 `stable.json` 渲染 ⇒ **改清单即生效**；只有首页文案、兜底版本号、兜底 SHA-256 需要同步改。
5. **中文/编码坑**：调 `node` 脚本**不要传中文路径参数**（先复制为 ASCII 名 `notes.md`）；PowerShell 读 UTF-8 文本要用 `-Encoding UTF8`（否则 `ConvertFrom-Json` 报错、日志看起来乱码）；`.cmd` 脚本必须以 **GBK(936)** 保存。
6. **旧版分流靠查询串**：`RewriteCond %{QUERY_STRING} version=(...)` 命中即返回 `stable-legacy.json`（version=3.0.0 ⇒ 客户端判「已是最新」静默跳过）。要屏蔽更多旧版，只改这一行正则并 `httpd -t` + `systemctl reload httpd`。
7. **上传/复核铁律**：大文件逐个 `scp`；清单最后传；上传后**服务端 + 公网双复核**（下载回本地比对 SHA-256 / exe MD5）。

### 12.5 发布前自检 16 项（逐条勾选，缺一不可）

1. `go vet ./...` 通过 2. `go test ./...` 全绿 3. `npm run build`（vue-tsc）通过 4. 构建产物无 `VITE_DEV_TOOLS`
5. exe 属性：`0x20B`、`subsystem=2`（GUI）、大小合理、图标 `3:6 14:1`（`node 06-交付发布\icon-replace\probe-res.js <exe>`）
6. exe 内嵌本版新功能字面量 7. `appVersion` 已注入（启动日志核对「版本=X.Y.Z」）
8. 新版自身不误报（日志「自动检查更新：当前已是最新版本」）9. 旧版能收提示（旧 exe 日志「发现新版本 当前=… 最新=…」）
10. full.zip 内源码类文件数 = 0 11. update.zip 与 full 内 exe 同一 MD5
12. 公网下载两包 SHA-256 与本地一致 + 包内 exe MD5 与本地一致
13. 旧版屏蔽规则仍生效（`?version=<旧版>` → legacy；`?version=<上一版>` → 新清单）
14. 老配置兼容（settings.json 宽松解析，删字段不炸）15. 首页文案/兜底值已更新 16. 使用说明与更新记录已同步
