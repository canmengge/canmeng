## 三、省时间的四条纪律（AI 必守）

1. **先查本表再开文件**，不要一上来全项目搜索（一次广搜能吞掉大量上下文，还常常被截断）。
2. **同一文件不要重复读**：一次用 `offset/limit` 读够，或只读改动附近的一段。
3. **搜索要窄**：给定目录 + 具体词；不要开大段上下文（`-C 3` 之类）。
4. **`本人备份AI不要动\` 只作只读参考源**——改编辑器时不在里面搜、不改、不删；要引用文档时从它复制。

## 五、踩坑经验（实测，别再踩第二次）

> **维护方式**：用户发「保存进度」时，若本轮踩了新坑，就往这里**追加一行**；没踩就不动。

| # | 坑 | 正确做法 |
| --- | --- | --- |
| 1 | `.cmd` 脚本存成 UTF-8 | 必须 **GBK(936)** 保存，否则 cmd.exe 中文乱码、连中文文件名都解析失败 |
| 2 | 工具执行的命令里出现 `%` | 会被路由到 **cmd** 外壳执行（PowerShell 脚本直接报"不是内部或外部命令"）；用 `[char]37` 拼接绕开 |
| 3 | `Select-String` 搜 GBK 文件里的中文 | 会假阴性（搜不到）。改用 `[System.IO.File]::ReadAllLines($f, GBK编码)` 再 `-match` |
| 4 | robocopy 用 `/XD dist` 或 `/XD bin` | 会误删 `node_modules` 内部同名目录。大目录（node_modules）**单独一趟**拷贝，不要用全局目录名排除 |
| 5 | 搬走源码后 `go build` 失败 | `main.go` 有 `//go:embed all:frontend/dist`，**`frontend\dist` 必须存在**（它是产物但编译期需要） |
| 6 | 改前端后重新打包 exe | 不需要。HMR 秒级生效；**只有改了 Go** 才用 `03-脚本\构建开发版.cmd` |
| 7 | 搜"关闭/打开"这类通用词 | 会命中几十处、输出被截断。先查本文件第二节落点表，直接开文件 |
| 8 | `.code-workspace` 双击打不开 | Windows 里**没有文件关联**。用 `03-脚本\用CodeBuddy打开工作台.cmd`，或 IDE 菜单「文件 → 打开工作区」。CodeBuddy 装在 `D:\CodeBuddy CN`，命令行启动器是 `bin\buddycn.cmd` |
| 9 | 多根工作区里各目录自己的 `.vscode\settings.json` **不生效** | 排除规则必须在 `.code-workspace` 的 `settings` 里**再写一遍**（现已两边同步，改一处要改两处） |
| 10 | `[System.IO.File]::AppendAllLines($f, $arr, $enc)` 在 PowerShell 5.1 报「找不到重载」 | 必须显式转成 `[string[]]`；否则写入不生效，还会误以为成功（本次就因此漏提交了一次台账记录） |
| 11 | `git push` 到 GitHub 报 `Failed to connect to github.com:443` / `Connection was reset`（`Test-NetConnection github.com -Port 443` 显示 **ping 通但 TCP 不通**，本机无代理） | **推送失败 ≠ 改动丢失**：本地 `commit` 与 `v<版本>` 标签照常完成、随时可回档；`push` 待网络恢复再补。应急可临时 `git -c http.proxy=http://127.0.0.1:<端口> push`（**不要改全局 git 配置**） |
| 12 | 改完 Go 只让用户"重启工具"，自己没构建 exe | **无效，会白跑一轮**：`启动HMR热更新.cmd` 只是挑 `04-运行环境\` 里**文件时间最新**的 `PVF工坊-开发人员专用*.exe` 来启动，**它只热更新前端、从不重新编译 Go**；"重启"只会把**旧 exe** 再跑一遍（2026-09-29 真实事故：改完 `services\import.go` 未构建，用户测到旧行为、误以为修复无效）。正确三步：① **AI 自己 `go build`** 出带时间戳的新 exe → ② **核验**新 exe 时间晚于源码修改时间、且在 `04-运行环境\` 中最新 → ③ 让用户**先关当前工具**再双击 HMR 脚本（详见 `01-项目开发规则.md` §0「改了 Go 的强制收尾三步」） |
| 13 | 改完 `.gitignore` 直接提交 | **规则写错会反向生效且静默**：放行行漏掉行首 `!` 就变成「忽略」；此时 `git add -A` **不会报错、只是不加该文件**，极易漏提交。改完**必须**用 `git check-ignore -v <路径>` 验证（**exit 0 = 仍被忽略；exit 1 = 已放行**），确认后再提交（2026-09-29 踩坑） |
