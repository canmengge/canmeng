## 一、三条铁律（F1~F3，最高优先级）

| | 铁律 | 含义 |
| --- | --- | --- |
| **F1** | 内核性能骨架冻结，只加功能 | 冻结层**只允许「补功能」，禁止「改实现」**；禁止以重构 / 优化 / 统一风格为由动解析、索引、写回算法 |
| **F2** | 性能只许变好，不许变差 | 打开 / 建索引 / 合计 / 内存 / 搜索索引五项 ≤ 原版基线；任一项超标 = 不得发版 |
| **F3** | 新增功能不得占用打开热路径 | 新功能必须惰性 / 按需 / 异步 / 可关闭；**禁止在 `Open` 与 `buildIndex` 之间插入任何同步全量工作** |

**违反 F1~F3 ⇒ 改动回退**（不是记录、不是例外）。

## 二、冻结 vs 可写（改哪里，先看这张）

| 层 | 路径 | 状态 |
| --- | --- | --- |
| 内核 | `internal\pvf\`、`internal\annotations\`、`internal\rendering\`、`internal\script\`、`internal\version\`、`internal\npk\`、`internal\preview\` | **冻结**：只补功能，禁改实现 |
| 服务层 | `services\*.go` | **可扩**（守 F3）← **新功能的主要落点** |
| CLI | `cmd\*` | 可扩（追加子命令，不改既有语义） |
| 前端 | `frontend\src\*` | 可扩 |
| 配置 | `config\*.json` | 可扩；业务规则外部数据，不硬编码 |
| 新增包 | `internal\logging\`、`internal\apppaths\` | 可扩（**不得**在 Open 路径插同步打点） |

## 三、🔴 红灯文件 5 个（动它们之前先想清楚）

## 五、明令禁止（借"优化 / 整合"之名的重构）

- 改 `internal\pvf\` 的解析 / 索引 / 写回算法、数据结构、并发模型
- 统一命名风格、格式化冻结层文件、调整文件划分
- 在 `Open` / `buildIndex` 内新增日志打点、统计、校验、预加载
- 重跑第四节里已回退的性能方案

## 六、什么时候必须跑 bench

| 情况 | 动作 |
| --- | --- |
| 触碰 `internal\pvf\` 下**任何**文件（哪怕只改一行注释） | 五项全测 + **F1 红线告警** |
| 发版候选 | 跑一次 |

## 七、新增功能的四条约束

1. **惰性 / 异步 / 可关闭 / 有进度** —— 长任务必须可取消
2. **外部数据** —— 校验规则、对象视图规则、禁动表一律 `config\*.json` + embed，**不硬编码进 Go**
3. **可回退** —— 一个功能一个补丁，能单独不合入，不做"一坨整合包"
4. **默认不破坏既有行为** —— 拦截 / 保护类功能**默认关闭**并提供设置开关
