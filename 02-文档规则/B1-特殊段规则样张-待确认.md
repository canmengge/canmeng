## 0. 先说最重要的发现：真实段有 **4 种形态**，不是"都是等宽表"

| 形态 | 实测例子 | 现成引擎能否表达 |
| --- | --- | --- |
| ① 等宽行表 | `[independent drop]` 17 token/行、`[list]` 2 token/行 | ✅ **能**（`kind: table` + `rowTokens`，纯数据） |
| ② 定长循环（"两列 / 四列"） | `[need item]` = 物品 数量 交替、`[add upgrade rate]` = 等级 比率 交替 | ✅ **能**（`rowTokens` 设 2 / 4，纯数据） |
| ③ 固定头 + N 组循环 | `[dungeon condition]` = 4 个固定值 + N×(物品, 数量) | ⚠ **要加规则字段**（"前置固定 + 循环组"），Go 侧小改 |
| ④ 包装段 / 键值块 | `[replace list]`（里面套 `[dungeon condition]`）、`[shop]`（category / item shop / npc index…） | ❌ **要加新 `kind`**（Go 侧改；`internal/formview/rules.go` 现在只有 `table` 一种） |

⇒ **B1 不是"纯补数据"**：①② 是纯数据（今天就能做），③④ 要先给规则模型加两种表达（Go 侧）。
⇒ **好消息**：B1 点名的 `[dungeon condition]` 就住在**已经建好规则**的 `etc/independent_drop.etc` 里 ⇒ 属于「给已有 format 补段」，比新开文件族便宜。

```
	[list]
```

- ❓ **新发现**：实际数据里第三列「掉落方式」还有取值 **`5`**（9 处），且这些行后面跟的不是 `[list]` 而是 `[replace list]`：**`5` 是不是"条件替换列表"？** 若是，现有 `links` 的 `when: ["1","2"]` 要加上 `"5"`（目标段改成 `replace list`）。

## 2. `list`（已有规则，作对照基准）

## 3. `[dungeon condition]`（形态 ③：固定头 + N 组循环）← **B1 点名的段**

真实片段（首次出现在第 3278 行，全文件 ×9）：

```
	[replace list]
		[dungeon condition]
			1	100000214	1	2	100322784	100	100390407	100	100170687	100	100345311	100	100345345	100	100345346	100	100345347	100	100345348	100
	[/replace list]
```

**我的读法**（待你确认）：`1 | 100000214 | 1 | 2` 是 4 个固定值，后面是 **8 组 `(物品ID, 数量)`**，即 `100322784×100、100390407×100、…、100345348×100`。

拟规则（形态③需要新字段，这里用 `prefix` + `loop` 表达，**名字可改**）：

```json
{
  "section": "dungeon condition",
  "label": "地下城条件替换",
  "kind": "table",
  "prefix": [
    { "label": "条件类型", "type": "enum", "values": { "1": "?" } },
    { "label": "条件编号", "type": "int" },
    { "label": "?", "type": "int" },
    { "label": "物品组数", "type": "int" }
  ],
  "loop": {
    "rowTokens": 2,
    "columns": [
      { "label": "替换物品", "type": "ref", "ref": "equipment|stackable" },
      { "label": "数量", "type": "int" }
    ]
  }
}
```

❓ 请确认这 4 个固定值分别是什么（我只敢确定"条件编号"和"物品组数"这两个位置可能对）：
1. 第 1 个 `1` = 条件类型（枚举）？都有哪些取值？
2. 第 2 个 `100000214` = 地下城/条件编号？
3. 第 3 个 `1` = ？
4. 第 4 个 `2` = 物品**组数**（还是别的计数）？实测每组都是 2 个 token 吗？

## 4. `[replace list]`（形态 ④：包装段）← 需要新 `kind`

真实片段：`[replace list]` 里面**只装一个** `[dungeon condition]`，随后 `[/replace list]`，紧跟着是**一条 17 token 的独立掉落行**（掉落方式 = 5）。

```
	[replace list]
		[dungeon condition]
			1	100000214	...
	[/replace list]
		0	109011084	0	40	40	40	40	40	1	1	1	1	1	0	0	-1	5
```

- 它**不是行表**（自己不带数据行），是"给下一行掉落配置挂条件"的**包装/限定段**。
- 拟规则（新增能力）：`"kind": "wrapper"`，声明"我内部的 `[dungeon condition]` 要挂到我后面的那条行上"。

❓ 请确认：`[replace list]` 与"它后面那条掉落行"的对应关系是**紧跟一行**吗？（我实测 9 个 `[replace list]` / 9 个 `[dungeon condition]` / 9 条掉落方式=5 的行，数量对得上，所以推测是"一对一、紧跟"。）

## 5. 定长循环（形态 ②）：`[need item]` / `[add upgrade rate]` ← 纯数据就能做

```
[group]
	[index]
		1
	[need item]
		10306750	75	10158964	20	10309021	5
	[/need item]
	[min upgrade]
		10
	[add upgrade rate]
		11	1.2	12	1.4	13	1.599	14	1.8
	[/add upgrade rate]
	[card enchant need item]
		2	0	300000	3	0	1000000	6	0	2000000
	[/card enchant need item]
	[broad cast]
	[show effect]
[/group]
```

拟规则（都是"2 token 一组的循环"，现成 `rowTokens: 2` 直接支持）：

```json
{ "section": "need item", "label": "升级所需材料", "kind": "table", "rowTokens": 2, "maxOccurrences": 500,
  "columns": [
    { "label": "物品", "type": "ref", "ref": "equipment|stackable" },
    { "label": "数量", "type": "int" } ] }

{ "section": "add upgrade rate", "label": "追加提升成功率", "kind": "table", "rowTokens": 2, "maxOccurrences": 500,
  "columns": [
    { "label": "等级", "type": "int" },
    { "label": "成功率(%)", "type": "rate", "scale": 1 } ] }
```

❓ 请确认：
1. `[need item]` = 物品 / 数量 交替？（`10306750 75` → 物品 10306750 要 75 个）
2. `[add upgrade rate]` = 等级 / 成功率 交替？`1.2` 是"1.2%"还是"1.2 倍"？（我按百分比写了 `scale: 1`）
3. `[card enchant need item]` 是 **3 个一组**（`2 / 0 / 300000`＝等级 / ? / 费用？）—— 中间那个 `0` 是什么？

**我的读法**：开头两个值 = `1`（启用自定义？）+ `` `charm_upgrade_table` ``（表名，反引号串），后面是 **N 组 3 个数**：`等级 / 0 / 数值`（`1 0 102`、`2 0 108`、`3 0 118` … 直到 `100 0 1500`）。

```json
{
  "section": "use costom upgrade type",

    { "label": "启用", "type": "enum", "values": { "0": "否", "1": "是" } },
    { "label": "表名", "type": "text" }
  ],
  "loop": {
    "rowTokens": 3,
    "columns": [
      { "label": "等级", "type": "int" },

  }
```

❓ 请确认：每组中间的 `0` 是什么？（全程都是 0 —— 是不是"保留位 / 未使用"？）
