**★ HMR 热更新 = 默认开发测试通道（2026-09-28 用户定，硬性；修改/操作编辑器一律走这条，除非用户明确说「换种方式」）**：

* **默认口径（必须执行）**：改编辑器前端（`frontend\src`）时**不跑任何构建**（不 `build:fast`、不 `npm run build`）、**不打包/不复制 exe**；改完源码直接告知用户查看——界面由 HMR 自动更新。日常不再执行 §E.1 产物交付流程。
* **用户侧入口（唯一）**：双击 `04-运行环境\HMR 热更新\启动HMR热更新.cmd` → 自动起前端开发服务器（`127.0.0.1:9255`）并以外部开发服务器模式启动程序；用户需保持“前端开发服务器”窗口开着。
* **原理（无需改 Go、无需重编）**：程序内置 Wails 官方开关 `FRONTEND_DEVSERVER_URL`；页面仍从 `http://wails.localhost:9255` 加载，程序只把**静态资源**转发给 vite，`/wails/*`（打开 PVF / 保存 / 索引 / 注释 / AI）仍由程序自身处理 ⇒ 接口与正式版完全一致。**不设该环境变量时行为 = 内嵌资源**，正式/内嵌模式零影响。
* **支持范围**：改现有 `.vue / .ts / .css` → 组件级热替换（不丢状态）；新增组件/面板（被 import）→ 自动编译生效；改 `main.ts` / `App.vue` 顶层结构 / 全局 store / `index.html` → vite 自动整页刷新（需重新打开文件一次）；改 `vite.config.ts` 或新增依赖 → 重启“前端开发服务器”窗口。
* **例外（仅这三种情况才构建）**：① 用户明确要求换方式 / 要正式成品；② 改了 Go（`main.go` / `services\` / `internal\`）⇒ 必须 `go build -trimpath -ldflags "-s -w" -o build\pvfine-devkit.exe .` 并复制为带时间戳的新文件名（主名尽力覆盖），再重启程序（Go 无法热更）；③ HMR 不可用（dev server 未起 / 端口占用）⇒ 回退 `build:fast` + `04-运行环境\启动开发版.cmd`（磁盘 dist 模式）。

### 5.5 工具链坑（实测，必须遵守）

| 坑 | 现象 | 规避 |
| --- | --- | --- |
| **`.ps1` 必须 UTF-8 with BOM** | 无 BOM 的 `.ps1` 被 Windows PowerShell 5.1 按 **ANSI/GBK** 读取，中文变乱码（`璺宠繃`）→ `Unexpected token` 解析失败，脚本完全不可用 | 落盘后追加 BOM：`[System.IO.File]::WriteAllText($p, $c, (New-Object System.Text.UTF8Encoding($true)))`；或改用 `pwsh`（若可用）。**`.js` / `.json` 无此问题**（Node 按 UTF-8 读） |
| **命令里的中文字面量路径可能被改写** | `Test-Path '…PVFINE编辑器（兼容版）…'` 误报"路径不存在"，而 `Get-ChildItem '…PVFINE编辑器*'` 通配符正常 | 路径含**中文全角括号**时，改用通配符枚举前缀，或先定位再拼接；遇到"路径不存在"先怀疑编码而非真缺文件 |
| Go 依赖拉取 | 默认代理不可达（IPv6 超时） | 必须 `$env:GOPROXY='https://goproxy.cn,direct'` |
| `-race` 不可用 | 本机无 gcc | 用 `go vet` + 压力单测替代，并断言结果一致性 |
| 前端无单元测试 | `frontend` 无 `*.test.ts` | 用 `npm run build`（含 `vue-tsc`）作为**类型级**自动验证；功能行为需人工看（U2） |
| ⚠ **CLI 源码基线不一致（高危，2026-09-24 实测）** | 镜像 `pvfine-main\cmd\pvf-cli\main.go` 是**旧版**（**4,484 B**，不含 `extract/strget/doc/saveas`）；权威版在 `pvfine-main-源码-0.6\…\cmd\pvf-cli\main.go`（**44,579 B**，MD5 `C4EF4BFB…`），与工作台 `_ai-work\src\pvfine-main\…` **逐字节一致**。从镜像构建 CLI 会**退化掉 `extract/strget/doc`**，直接摧毁模块 B 的日常链路 | **禁止**用镜像 `cmd\pvf-cli` 构建/部署 CLI。CLI 一律用 `_ai-work\bin\pvf-cli-plus.exe`（11,052,032 B，MD5 `6CE9A83D…`）或从 `_ai-work\src\pvfine-main` 构建。`build.ps1 -Build` 已加 **MD5 守卫**，不一致时拒绝构建 CLI 并打印指引 |
| ⚠ 镜像与基线并非全量一致 | 「源码基线逐文件一致」只对**抽查过的文件**成立；至少 `cmd\pvf-cli\main.go` 不一致（镜像旧、基线新，因基线快照额外并入了工作台的增强 CLI） | 涉及"能否重建某产物"的结论，必须**逐文件比对 MD5**，不得由抽查外推 |
| ⚠ **更新包下载超时** | Wails updater 的 endpoint provider **默认 HTTP 超时 30 秒**；10MB+ 的更新包在慢速网络上必然 `context deadline exceeded`（表现为"更新失败"） | `endpoint.Config.HTTPClient` 必须传 `&http.Client{Timeout: 15 * time.Minute}`（manifest 与 artifact 下载共用该 client） |
| ⚠ **大文件 scp 中途超时** | 一次性 scp 多个大 zip 到服务器会 `Connection timed out`，出现「stable.json 已更新但 zip 仍是旧字节数」的不一致状态 | 大文件**逐个** scp，带 `-o ServerAliveInterval=15`；传完必须**服务端复核** `sha256sum` 与字节数 |
