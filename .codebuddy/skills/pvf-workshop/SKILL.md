## 二、硬性纪律（每条都真踩过坑）

### 1. 改了 Go，必须自己构建 + 核验 + 告知正确启动方式

- 自己跑构建，**不要只说"重启工具"**（用户会以为改了没生效，白跑一轮）。
- 构建后**核验 exe 时间戳最新**（运行区里挑「文件时间最新」的那个启动）。
- 明确告知用户：**先关掉正在运行的工具，再双击** `04-运行环境\HMR 热更新\启动HMR热更新.cmd`。

用 `scripts/build-dev.ps1` 做这件事（它会顺带跑核验并打印该告知用户的原话）。

### 2. 只有改了 Go 才构建；纯前端改动不要打包

- 前端源码（`.vue` / `.ts` / `.css`）改动 → **走 HMR**：双击 `04-运行环境\HMR 热更新\启动HMR热更新.cmd`，保持「前端开发服务器」窗口开着，保存即秒级生效（约 1 秒），**不构建、不打包**。
- 备选（磁盘资源模式）：`04-运行环境\刷新前端并启动.cmd` → 构建 `frontend\dist-dev` 并启动；`04-运行环境\启动开发版.cmd` 读 `frontend\dist-dev`。

### 3. 改 `frontend\src\stores\*.ts` 必须告知"需重启一次"

Pinia store **不能靠 HMR 热替换**（会出现"界面还在、保存读到空状态"）。改 store 后必须让用户重启程序，不能承诺热更新。

### 4. 每轮改动 = commit + `v<patch+1>` 标签

- 先看已有标签（`git tag --sort=-v:refname | Select-Object -First 6`），**不要重号**。
- 标签格式 `v4.6.2` 这类；正式版用 `v4.6.0`（三段）。
- 提交前先 `git diff --numstat` 看改动比例，**防止行尾符被整体改写**（整篇 +/- 说明行尾变了，要先转 LF）。

### 5. `.cmd` 脚本必须以 **GBK(936)** 保存

新建或改写 `.cmd` 后要确认编码，否则中文注释会乱码、命令可能失效。

### 6. 用户红线：只有"显式保存"才允许写回归档

- 编辑器**绝不自动保存**（失焦 / 滚动 / 切标签 / 关窗冲刷全部不允许）。
- 大文件（TXT 视图）改动只留在前端，必须用户点「保存」或 Ctrl+S 才写回归档内存；再由工具条「保存 PVF」落盘。
- 违反这条 = 用户打一半的字被写进去，**不可接受**。

### 7. 大文件卡死，先判「通道 vs 算法」

- 先量：是"文本交给 WebView"这条**通道**慢，还是解析/渲染**算法**慢。
- 大文件的价值全在「**文本不进窗口**」：按视口取行（`GetFileLines`）+ 按视口取注解（`GetWindowAnnotations`）+ 查重在 Go 侧扫（`CheckListDuplicatesWithOverlay`）。
- 补功能只走**段级通道**；折行不可用（会破坏「行号 × 20px」虚拟定位）。

### 8. 碰 `internal\pvf\` 或 `services\search_index.go` 前，先读 `编辑器内核红线.md`

F1 冻结层不许改写回算法 / F2 五项 benchmark 不许变差 / F3 不许在 `Open` 与 `buildIndex` 之间插同步全量工作。只允许**加回调**式扩展。

### 9. 提交前确认没把大产物带进 git

`frontend\dist`、`bin`、依赖目录、`06-交付发布` 的包都不进仓库（已被忽略）；提交后用 `git status --short` 复核是干净的。

## 三、常用操作 → 用哪个脚本

所有脚本在 `scripts/` 下，**PowerShell 直接跑**（本机 `python` 不可用，脚本一律用 PowerShell）。

| 要做的事 | 命令 |
| --- | --- |
| 构建开发版 exe + 核验 + 打印该告知用户的原话 | `scripts/build-dev.ps1` |
| 核验正式版 exe（PE 头 / 图标 / 版本 / 内嵌字面量 / 哈希） | `scripts/verify-exe.ps1 -Exe "<exe路径>" -Literals "4.6.0","取消封包"` |
| PVF 内容分析（列文件 / 统计扩展名 / 读单文件 / 搜索 / 按清单提取） | `scripts/pvf.ps1 -Action <动作> [...]` |

> `pvf.ps1` 每次都要重新打开 544 MB 的归档（约 10 秒），**一次调用只做一个动作**；需要多次分析时先把路径清单导出成文件复用。

### ⚠️ 脚本编码（改写脚本前必读）

本技能三个 `.ps1` 一律存为 **UTF-8 with BOM**。

Windows PowerShell 读「UTF-8 **无 BOM**」的 `.ps1` 会按 ANSI(GBK) 解码 → 中文注释变乱码 → **字符串被截断、直接报语法错**（本项目 `.cmd` 要 GBK，而 `.ps1` 要 UTF-8+BOM，两者规则相反，别记混）。

改写脚本后用下面这句补回 BOM：

```powershell
$p = "<脚本路径>"
$t = [System.IO.File]::ReadAllText($p, [System.Text.UTF8Encoding]::new($false))
[System.IO.File]::WriteAllText($p, $t, [System.Text.UTF8Encoding]::new($true))
```

自查：`[System.Management.Automation.Language.Parser]::ParseFile($p, [ref]$null, [ref]$errs)`，`$errs.Count` 必须为 0。

## 四、发布正式版（详细步骤看台账 §12，这里只补"最容易漏的"）

完整流程：**台账 `02-实施计划与执行台账.md` §12.2 十步 + §12.5 自检 16 项**。执行时**逐条勾**，不要凭记忆。

AI 侧容易漏的三条（都真实发生过）：

1. **正式构建参数必须完整**（漏了就出黑窗或没版本号）：
   ```powershell
   go build -tags production -trimpath -buildvcs=false `
     -ldflags "-w -s -H windowsgui -X main.appVersion=<X.Y.Z>" `
     -o "<输出 exe>" .
   ```
   漏 `-H windowsgui` ⇒ `subsystem=3`（控制台黑窗）；漏 `-X main.appVersion` ⇒ 版本号停在 `0.0.0`，自动更新失效。
   构建完用 `scripts/verify-exe.ps1` 核验，**不要靠眼睛**。

2. **发布时必须同步"程序内欢迎页更新记录"**
   除了客户端目录的《更新记录.md》，还要改 `01-源码\frontend\src\components\EditorTabs.vue` 的 `changelogEntries`（新版本加在最前，只写用户能感知的变化）。此前只改了前者，程序首页那份漏掉过。

3. **首页兜底值三处**（`/pvf/index.html`）：版本号、下载链接文件名、完整包 SHA-256；外加"新文件名 / 请删除旧 exe"的提示文案。
   参考上一版留档：`06-交付发布\release-<版本>\index-online-<版本>.html`。

**上传/复核铁律**：大文件逐个 `scp`，**清单最后传**；上传后服务端 + 公网双复核（把两个包从公网下载回来比对 SHA-256 与包内 exe 的 MD5）。
